# 更新日志写法

修改 `CHANGELOG.md` 时，如存在 `CHANGELOG.zh-CN.md`，必须同步更新中英文两份日志；两份含义保持一致，但表达要符合各自语言习惯。

## 标题分类

新增更新日志只使用三类标题，不要新增性能、UI、文档、国际化、限制等其它标题，除非用户明确要求。

- 英文：`### 🚀 New Features`、`### ✨ Improvements`、`### 🐛 Bug Fixes`
- 中文：`### 🚀 新增功能`、`### ✨ 功能优化`、`### 🐛 问题修复`

标题选择按用户可感知变化判断：

- 新增能力放 `New Features` / `新增功能`。
- 已有能力变得更快、更顺、更好用、更清晰，放 `Improvements` / `功能优化`；性能优化通常归入这里。
- 明确错误行为、兼容性问题或回归修复，放 `Bug Fixes` / `问题修复`。

## 条目位置规则

- **必须追加在列表末尾**：在 `[Unreleased]` 下记录更新时，新条目**必须追加到对应分类列表的最下方（末尾）**。严禁直接插在分类首行，以保持条目随开发进程有序递增，避免打乱已有条目的时间线或核心亮点展示。

## 条目写法与语言风格

- **面向普通用户，彻底杜绝技术黑话**：
  - 说明只写"用户在什么场景遇到了什么、现在能看到/感受到什么效果"。
  - 严禁出现底层实现机制、架构概念或 Bug 根因代码词（如"虚拟滚动"、"DOM 节点"、"离屏卸载"、"MutationObserver"、"Shadow DOM"、"防抖节流"、"生命周期"、"数据流"等）。用户关心的是"体验有没有变好"，不关心"代码怎么坏的、怎么修的"。
- **标题人话化（2~8 字自然短语）**：
  - 格式：`- **功能点/场景标题** — 一句说明。`
  - 标题应概括用户能理解的功能或现象（如"大纲条目错位"、"面板边缘误触"、"输入框自动隐藏"），禁止将两个技术术语生硬拼成标题。
- **说明结构与克制表达**：
  - **问题修复**：`在什么场景下，修复了某种具体异常表现，恢复正常效果。`
  - **功能优化/新增**：`在什么场景下，增加了某种能力或改进，用户获得了什么实际便利。`
  - 避免"更丝滑""更好用""更轻快"等泛泛空话，直接说清楚具体改善了什么；中文优先用"现在…""修复…""避免…"，英文说明优先用 `now supports`、`Fixed issue where...`。
- **合并相关改动**：不要逐条直译 Git Commit；相关联或用户感知为一个整体的改动，合并为一条精炼的用户日志。
- **一个分支一条日志**：一个分支（一个 PR）无论改了多少处、涉及多少个站点，最终只写一条日志；同一分支的多个相关修复必须合并为一条概括性条目，禁止按站点、模块或 commit 拆成多条并列。分支持续开发过程中新增日志时，先检查是否已有本分支的条目，有则改写成合并后的一条。

## 正反例对照

| 类型 | ❌ 错误写法（技术黑话/拗口难懂） | ✅ 正确写法（通俗人话/直观清晰） |
| :--- | :--- | :--- |
| **问题修复** | `- **ChatGPT 虚拟滚动下的大纲归组** — 修复 ChatGPT 长对话中因虚拟滚动卸载离屏内容，导致已缓存的回答标题在大纲中错位归入相邻提问或出现次序跳变的问题。` | `- **ChatGPT 长对话大纲错位** — 修复 ChatGPT 长对话滚动时，部分回答标题在大纲中被错误归入相邻问题或次序错乱的问题。` |
| **功能优化** | `- **MainPanel 单 Tab DOM 门控优化** — 在 MainPanel.tsx 中当 visibleTabs.length <= 1 时移除 .gh-panel-tabs 节点渲染，节省 38px 空间。` | `- **单标签页自动隐藏** — 仅开启一个功能时自动隐藏顶部切换栏，释放纵向空间展示更多内容。` |
| **功能优化** | `- **快捷工具栏 z-index 与 pointer-events 调整** — 修复浮动面板 CSS 层级覆盖导致的 click 事件穿透捕获失效。` | `- **工具箱菜单被面板遮挡** — 修复吸附模式下点击快捷工具栏时菜单被面板盖住的问题，现在菜单始终位于面板之上。` |

## 编号与贡献者

如果变更来自 PR、issue 或外部贡献者，能确认时要在条目末尾保留编号和贡献者；不要遗漏，也不要凭空补。

- 单个来源：`(#645)`、`(#547, @urzeye)`
- 多个直接相关来源：`(#593, #625)`
- 中英文两份日志的编号和贡献者保持一致。
