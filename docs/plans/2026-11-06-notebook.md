# Notebook Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add Gemini Notebook as a built-in site supporting outline navigation, theme switching, panel avoidance, and prompt insertion.

**Architecture:** A dedicated Notebook adapter reads the three native content columns. Explicit navigation context keeps user navigation separate from conversation history, and scopes temporary anchors to the current content. Capability declarations gate unsupported entry points.

**Tech Stack:** TypeScript, React 18, Plasmo, Vite userscripts, native CSS.

---

## Task 1: Built-in adapter and registration

- Create `src/adapters/notebook.ts` and `src/adapters/notebook-config.ts`.
- Register the adapter and config in `src/adapters/builtin.ts`, `src/core/builtin-config-registry.ts`, and `src/platform/userscript/adapters-vendor.ts`.
- Add the site to `src/constants/defaults.ts`, capability declarations, content-script matches, extension permissions, and userscript matches.
- Extract source, conversation, and Studio outlines from the supplied `notebooklm.html`; only conversation includes user queries. Support ARIA heading levels 1–6 and source-scoped target lookup.

## Task 2: Navigation and supported entry points

- Share the current outline navigation context across `MainPanel`, `QuickButtons`, and `useShortcuts`.
- Isolate anchors by notebook, column, and current document; never fall back to scrolling another column when the selected document is closed.
- Disable conversation management, export, model locking, queue execution, and other unsupported site actions at entry points.
- Keep existing sites' navigation behavior intact.

## Task 3: Theme, avoidance, and input

- Read/write `bcsp` as `light`, `dark`, or `system` and synchronize the native theme using the supplied snapshot's theme variables.
- Reuse `LayoutManager` to reserve space around the native three-column workspace.
- Insert prompts into the central textarea with the native setter and input events.
- Add all new interface strings to all 11 application locales.

## Task 4: Verification

- Run a local browser fixture using `notebooklm.html`; assert heading counts, source isolation, scroll/anchor behavior, semantic heading lookup, input events, theme preferences, and avoidance geometry.
- Run targeted Prettier/ESLint checks, then `pnpm typecheck` and `pnpm registry:validate`.
- Run `pnpm build`, `pnpm build:userscript`, and `pnpm build:firefox` because the change touches content-script entry points and shared navigation.
- Inspect the final diff and branch status. Do not modify or commit the supplied snapshot.

No authenticated or online Notebook verification is required. This session implements the plan directly; commits and publishing are outside the requested scope.
